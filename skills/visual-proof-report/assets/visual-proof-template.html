Resumes interrupted work

PASS
killed at 25% complete ✓
Tested

What happens when the operation is stopped partway through and the app restarts.

Did

Interrupted the job at 25%, restarted the app, resumed. Verified the final result is byte-exact and recorded exactly once.

Why

Real machines sleep, crash, and drop connections mid-task.

If it failed

A half-finished job gets marked done, or every restart begins again from zero.

Example

Laptop lid closes mid-run → reopen later and the job finishes from its checkpoint, nothing duplicated.

evidence · SAMPLE-UAT-RESUME
interrupted_at=25% → restarted → resumed_from_checkpoint
result recorded exactly once · checksum matched expected
replay idempotent — no duplicate effects

Rejects unsafe input

PASS
valid input ✓ malformed → REJECTED 0 side effects
Tested

How the system responds to malformed and hostile input alongside valid input.

Did

Sent valid input plus four invalid variants. Checked every invalid case was rejected with a clear error and nothing changed.

Why

Bad input must never corrupt state or trigger hidden work.

If it failed

One malformed request could damage stored data or slip past a safety rule.

Example

A corrupted upload is refused with a clear message — nothing on disk changes.

evidence · SAMPLE-UAT-REJECT
invalid_cases=4/4 rejected · valid_case accepted
state_delta=0 work_delta=0 after each rejection
each rejection returned a typed, user-readable error

Handles realistic scale

PASS
10,000 records status: 4 queries no full scans
Tested

The same operations against a dataset the size of real production use.

Did

Loaded 10,000 records, ran the core operations, counted the database work per call and proved fixed ceilings with indexed lookups.

Why

Behavior that works on 10 rows must not crawl on 10,000.

If it failed

The app slows to a grind as real data accumulates, and one heavy query can scan everything.

Example

A full-size library → the status check answers in 4 queries instead of touching every row.

evidence · SAMPLE-UAT-SCALE
records=10000 page_size=200
statements: status=4 update=7 · no OFFSET
indexed seeks confirmed via query plans · real on-disk fixture
